# Hermes and Gnani speech integration research

## Hermes host

- The plugin targets v0.23.2 and Python 3.14. Hermes's 3.11–3.13 metadata exists for older installers to migrate. The host pins HTTPX 0.28.1 and websockets 15.0.1. Directory installs recognize dependencies in the manifest or adjacent pyproject. [Host constraints](https://github.com/NousResearch/hermes-agent/blob/v0.23.2/pyproject.toml) · [Plugin developer guide](https://github.com/NousResearch/hermes-agent/blob/v0.23.2/website/docs/developer-guide/plugins/index.md)
- Native STT takes a file and returns a success/failure envelope. Live STT takes 16 kHz mono s16le PCM. The host wrapper polls the plugin for partials and uses a 20-second finalization deadline. The cancellation path can abandon the inner session without calling its finalizer, so the Gnani worker also enforces its own idle and session bounds. [STT provider ABC](https://github.com/NousResearch/hermes-agent/blob/v0.23.2/agent/transcription_provider.py) · [Host live adapter](https://github.com/NousResearch/hermes-agent/blob/v0.23.2/tools/transcription_streaming.py)
- Hermes forwards STT model and language from `stt.gnani` and TTS model, voice, and speed from the root `tts` section. The dashboard merges discovered providers into existing enums. In v0.23.2, the STT selector is absent from the base schema, so the plugin is selected in YAML. Stock TTS setup fields for individual providers are curated, so the manifest exposes Gnani choices in its plugin settings. [STT dispatch](https://github.com/NousResearch/hermes-agent/blob/v0.23.2/tools/transcription_tools.py) · [TTS dispatch](https://github.com/NousResearch/hermes-agent/blob/v0.23.2/tools/tts_tool_plugins.py) · [Provider enums](https://github.com/NousResearch/hermes-agent/blob/v0.23.2/hermes_cli/web_server_config.py)
- Hermes can invoke up to three PCM streams for consecutive sentences. The plugin opens independent SSE responses and supports closing a response early. Hermes's Opus voice delivery can consume a complete OGG file. [TTS ABC](https://github.com/NousResearch/hermes-agent/blob/v0.23.2/agent/tts_provider.py) · [PCM integration](https://github.com/NousResearch/hermes-agent/blob/v0.23.2/website/docs/developer-guide/streaming-tts.md)
- Catalog validation verifies dependency compatibility, registration, credentials policy, and install-scan findings. Its entry pins a public immutable commit. [Catalog rules](https://github.com/NousResearch/hermes-agent/blob/v0.23.2/plugin-catalog/README.md)

## Gnani API decisions

- REST Prisma uses `audio_file`, a 30-second limit, and canonical `language_code`, `format`, and context field names. The SDK still sends some legacy aliases including `multi_lang_codes` and `keywords`. The SDK also owns the top-level `gnani` Python namespace, so the plugin uses HTTPX and websockets directly. [Prisma REST](https://docs.gnani.ai/api/STT/speech-to-text.md) · [SDK source](https://github.com/Gnani-AI-Mintlify/gnani-vachana/blob/7c31c8b2c8986955472ef3289b0ac4caf264f18e/gnani/stt/client.py)
- Realtime uses canonical upgrade headers, 1,024-byte binary audio frames, and a client `commit`. The API sends finalized numbered segments and does not specify an end-of-stream acknowledgment. The plugin waits for in-flight segments with a bounded drain. The limits summary and model-specific docs differ on live `previous_text`. The model and wire documentation specify it as an upgrade header. v2.5 uses explicit locales across all plugin transports. [Prisma realtime](https://docs.gnani.ai/api/STT/stt-websocket.md) · [Prisma v3.0 context](https://docs.gnani.ai/api/STT/models/prisma-v3.md#context) · [Limits summary](https://docs.gnani.ai/api/STT/limits.md)
- Batch requires separate create, start, status, file list, and signed transcript download operations. A presigned upload uses the v2 create route but the same v3 job management routes. Poll at least ten seconds apart. v2.5 omits the v3-only `format` field. [Batch introduction](https://docs.gnani.ai/api/STTBatch/Introduction.md) · [Create and upload](https://docs.gnani.ai/api/STTBatch/Create_Job.md) · [Signed results](https://docs.gnani.ai/api/STTBatch/Get_Job_Files.md)
- Timbre REST has native WAV, MP3, and OGG Opus. SSE supports raw linear PCM and a terminal `complete` event. The SDK's language validation differs from published `hi-en` support, and the v3.0 API can round speeds within its accepted range. The plugin accepts only its three effective speed values. WebSocket TTS accepts complete text just like SSE. [Timbre REST](https://docs.gnani.ai/api/TTS/tts-inference.md) · [SSE](https://docs.gnani.ai/api/TTS/tts-sse.md) · [WebSocket](https://docs.gnani.ai/api/TTS/tts-websocket.md) · [SDK TTS source](https://github.com/Gnani-AI-Mintlify/gnani-vachana/blob/7c31c8b2c8986955472ef3289b0ac4caf264f18e/gnani/tts/client.py)

## Live observations

- Timbre REST returned WAV with `0xFFFFFFFF` placeholders for RIFF and data lengths. The plugin completes these lengths from the response size before validating and publishing the file. Raw SSE PCM produced valid samples on both models.
- The documented presigned Batch creation endpoint returned HTTP 404 with the tested key. Multipart Batch creation, polling, and signed transcript downloads succeeded. The plugin reports the presigned failure with a way to submit a smaller file. The optional large-file smoke test retains the documented request so it can be rerun when the endpoint is available. [Batch presigned upload reference](https://docs.gnani.ai/api/STTBatch/Create_Job.md#presigned-upload-large-files)
